Claude for the lab: one-page quick reference

Human Oversight Systems Lab. Full detail is in the setup guide; this is the at-a-glance version.

1. Set up your account (about 10 min)

  • Instructions for Claude: paste the lab text (concise, voice rules, ask before multi-step).
  • Memory: generate off, import off.
  • Connector discovery: off. Location: off.
  • Artifacts and inline visualizations: on. AI-powered artifacts off.
  • Claude Code: auto-PR off, autofix-PR off, classify-sessions off.
  • Notifications: response completions on, code permission requests on.

2. Connect GitHub

  • Your lab GitHub access is set up; the lab repos are visible to you.
  • Settings → Connectors → GitHub → Connect (pre-approved, no wait).
  • In a chat: attach (+) → Add content from GitHub → pick repo + files.
  • Coding: set up local git (SSH key or gh CLI), then clone.

Usage limits (read this)

  • One shared budget across web chat, Claude Code, desktop.
  • A rolling 5-hour window plus a weekly cap. Resets roll, not at midnight.
  • Hit a limit and you pause until reset. No extra charge.
  • Stay under: fresh chat per topic, lighter model for routine work, no long unattended runs.
  • Blocked weekly a lot? Tell the PI; we will find a tighter workflow.

3. The four building blocks

Instructions standing guidance. You set your own.
Skills reusable task abilities. Use the approved set.
Plugins bundles of skills + connectors. PI installs.
Connectors links to outside tools (GitHub). PI approves.

PI curates the set; you personalize your instructions.

4. Three layers of instructions

Organization set by PI, applies to all, locked
Project per project (e.g. Knowledge Base)
Personal yours to set, in Profile

Higher layer wins. Add a personal one when you repeat yourself every session.

5. Work in projects, not loose chats

Project: your work
Knowledge base (set once): design docs, contracts, repo conventions.
Chats (many) scaffold, debug, draft, prep notes. All share the knowledge.
Loose chat Outside any project. Knows none of the lab context. Use only for throwaway, non-lab questions.

Keep projects coarse: one per real body of work, not one per task and not one catch-all.

The rules (non-negotiable)

  • No identifiable participant data in any chat, ever. De-identify first.
  • No free consumer AI tools for study work.
  • No new AI tool on study work without asking first.
  • Read every line of AI-written code or text before it ships.

Reach Claude

  • Web / desktop: main workspace; use the project.
  • Slack: ask the bot in our workspace.
  • Claude Code: terminal, IDE, or desktop, for repo work.

Making a skill

  • Done the same multi-step routine 3+ times? It may be a skill.
  • You cannot publish skills yourself; draft it and send to the PI.
  • PI reviews for safety and fit, then publishes to the lab.

Get help

  • Weekly PI office hours (time in the full setup guide).
  • The lab Slack, or message the PI.
  • Asking is never wrong. Write down the answer so you ask once.
